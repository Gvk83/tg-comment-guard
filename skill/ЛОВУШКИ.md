# Ловушки

Всё перечисленное — реальные ошибки, найденные при живом запуске бота, а не
теория. Каждая молчаливая: ничего не падает, в журнале чисто, а бот не работает.
Прочитай перед тем, как писать код или разворачивать.

---

## 1. Режим приватности в BotFather

**Симптом:** бот в чате, служба запущена — но не реагирует ни на одно
сообщение. В журнале тишина.

**Причина:** по умолчанию бот в группе видит только команды со слэшем.
Обычные сообщения ему не приходят вообще.

**Важное уточнение.** В документации Telegram есть исключение: *«Privacy mode
is enabled by default for all bots, except bots that were added to a group as
admins (bot admins always receive all messages)»* — **бот-администратор видит
все сообщения даже с включённым режимом приватности.**

Так что если бот сразу добавлен админом, он заработает и без этой настройки.
Но выключить её всё равно нужно: в тот день, когда у бота снимут или урежут
права администратора, он молча ослепнет — без единой ошибки в журнале.

**Решение:** @BotFather → `/mybots` → бот → **Bot Settings** → **Group
Privacy** → **Turn off**. Должно появиться «Privacy mode is disabled».

**Важно:** если бот уже был в чате, его надо **удалить и добавить заново** —
иначе настройка не подхватится.

**Проверка в коде:** `(await bot.me()).can_read_all_group_messages` — `True`
означает, что режим выключен. У бота-администратора это поле может быть
`False`, а сообщения всё равно приходить: поле отражает настройку, а не
фактический доступ.

## 2. `allowed_updates` без `callback_query`

**Симптом:** кнопки под сообщением нарисованы, при нажатии крутится индикатор
и ничего не происходит. Обработчик написан правильно, но не вызывается.

**Причина:** при запуске polling перечисляются типы событий. Если указать
только `message`, Telegram не пришлёт нажатия кнопок.

```python
# НЕПРАВИЛЬНО — кнопки мертвы
await dp.start_polling(bot, allowed_updates=["message", "edited_message"])

# ПРАВИЛЬНО
await dp.start_polling(
    bot, allowed_updates=["message", "edited_message", "callback_query"]
)
```

Проще всего вообще не указывать `allowed_updates` — aiogram подставит нужные
сам, исходя из зарегистрированных обработчиков.

## 3. Скрытые ссылки в разметке

**Симптом:** спамер пишет «Подробности [тут](https://t.me/scam)» — слово «тут»
кликабельно, адрес спрятан. Фильтр по видимому тексту не находит ничего.

**Причина:** `message.text` содержит только видимый текст. Адрес лежит
в `message.entities` с типом `text_link`.

```python
def hidden_links(message):
    urls = []
    for entity in (message.entities or []) + (message.caption_entities or []):
        if entity.type == "text_link" and entity.url:
            urls.append(entity.url)
        elif entity.type == "text_mention" and entity.user:
            urls.append(f"@{entity.user.username or entity.user.id}")
    return urls
```

Отдельно: сообщение может быть **вообще без текста** — картинка без подписи,
но со ссылкой в разметке. Проверяй такие тоже.

## 4. Служебные сообщения о входе в группу

**Симптом:** чат завален надписями «X теперь в группе». Владелец ищет, где это
выключить в настройках Telegram, и не находит.

**Причина:** такой настройки нет. Убрать их может только бот с правом удаления.

```python
dp.message.register(
    handler,
    F.chat.type.in_({"group", "supergroup"}),
    F.new_chat_members | F.left_chat_member | F.new_chat_title
    | F.new_chat_photo | F.delete_chat_photo,
)
```

Регистрируй этот обработчик **раньше** проверки текста: у служебных сообщений
текста нет, и обычный обработчик их пропустит.

Уже накопившиеся старые сообщения бот не уберёт — см. пункт 5.

## 5. Ограничение в 48 часов

Бот не может удалить сообщение старше 48 часов. Сразу предупреди владельца:
старый мусор придётся чистить вручную или смириться, автоматически исчезать
будет только новый.

## 6. Telegram не даёт боту написать первым

**Симптом:** в журнале `Bad Request: chat not found` при попытке отправить
уведомление владельцу. Токен верный, ID верный.

**Причина:** бот не может начать диалог. Пока человек не нажал **Start**
в личке бота, отправка ему невозможна.

**Решение:** попроси владельца открыть бота и нажать Start. Это обязательный
шаг, без него уведомления и управление работать не будут.

## 7. `ProtectSystem` в systemd и запись настроек

**Симптом:** бот работает, но настройки, изменённые из Telegram, пропадают
после перезапуска. Или запись падает с `Read-only file system`.

**Причина:** усиление безопасности службы делает каталоги доступными только
для чтения.

**Решение:** явно разреши запись в каталог приложения:

```ini
ProtectSystem=full
ReadWritePaths=/opt/moderator
```

Файл `.env` должен принадлежать пользователю службы и иметь права `600`.

## 8. Публичный IPv4 у хостера платный отдельно

**Симптом:** обещал владельцу 330 ₽/мес, в счёте 480 ₽.

**Причина:** у многих российских хостеров публичный IP-адрес тарифицируется
отдельно, примерно 150 ₽/мес. В цене тарифа он не учтён.

**Решение:** называй сумму сразу с IP. И предупреди: вариант «без публичного
IP» брать нельзя — сервер останется без интернета, бот не свяжется с Telegram.

## 9. Файлы macOS в архиве

**Симптом:** при распаковке на сервере появляются файлы `._bot`, `._deploy`.
Python может на них споткнуться.

**Причина:** macOS кладёт в tar служебные файлы метаданных.

**Решение:**

```bash
tar --exclude='._*' --exclude='.DS_Store' -czf архив.tgz .
# и на сервере после распаковки:
find /opt/moderator -name "._*" -delete
```

## 10. Токен

Никогда не проси прислать токен в переписку и не печатай его в выводе.

Правильный путь — скрытый ввод на машине владельца и передача сразу на сервер:

```bash
read -rs TOKEN
printf '%s' "$TOKEN" | ssh -i ~/.ssh/ключ root@IP 'read -r T; sed -i "s|^BOT_TOKEN=.*|BOT_TOKEN=${T}|" /opt/moderator/.env'
```

Токен не попадёт ни в чат, ни в историю команд. В журналах маскируй его:

```bash
journalctl -u moderator | sed 's/[0-9]\{8,\}:[A-Za-z0-9_-]\{30,\}/***/g'
```

## 11. Кнопки не должны дублировать друг друга

Постоянная клавиатура под полем ввода и кнопки внутри сообщения — разные вещи.
Если положить одно и то же в оба места, интерфейс выглядит сломанным.

Разведи роли: клавиатура под полем ввода — **просмотр** (состояние, статистика,
журнал). Кнопки в сообщении — **действия** (сменить режим, пауза, перезапуск).

Список команд для кнопки «Меню» регистрируй с областью видимости владельца,
иначе участники группы увидят команды управления:

```python
await bot.set_my_commands(commands, scope=BotCommandScopeChat(chat_id=admin_id))
```

## 12. Анонимный администратор и связанный канал

**Симптом:** бот удалил сообщение администратора или забанил собственный
канал. Проверка «не трогать администраторов» вроде бы есть.

**Причина:** анонимный админ пишет **от имени группы**, а не от себя.
В поле отправителя приходит системный `1087968824` (@GroupAnonymousBot),
а `sender_chat` — сама группа. В списке `get_chat_administrators()` этого
идентификатора нет.

Отдельно: пост канала, автоматически пересланный в группу обсуждений, тоже
приходит от `sender_chat`. Забанить связанный канал — сломать комментарии.

**Решение:**

```python
SYSTEM_SENDERS = frozenset({1087968824, 777000})

def is_protected(user_id, chat_admins, *, sender_chat_id, chat_id, linked_chat_id):
    if sender_chat_id is not None and sender_chat_id in (chat_id, linked_chat_id):
        return True          # анонимный админ или связанный канал
    if user_id in SYSTEM_SENDERS:
        return True
    ...
```

Спам **от постороннего** канала при этом банить нужно — через
`ban_chat_sender_chat()`.

## 13. `reply_to_message` есть у каждого комментария

**Симптом:** фильтр почти не срабатывает, все сообщения получают скидку
«это ответ участнику».

**Причина:** в чате комментариев **любое** сообщение формально отвечает
на автоматически пересланный пост канала. Проверка «есть `reply_to_message`
— значит живой диалог» срабатывает на всех.

**Решение:** отсекай автопересланный пост:

```python
is_reply_to_user = bool(
    message.reply_to_message
    and message.reply_to_message.from_user
    and not message.reply_to_message.is_automatic_forward
)
```

## 14. Поиск слов без границ

**Симптом:** «Я вчера **зараб отал**ся до ночи» удалено как предложение
работы. «Пора **на смену** масла» — тоже.

**Причина:** поиск фразы подстрокой. «заработался» содержит «работа»,
«на смену масла» содержит «на смену».

**Решение:** ищи по границам слова:

```python
re.compile(rf"(?<![0-9а-яa-z]){re.escape(phrase)}(?![0-9а-яa-z])")
```

Отдельная ловушка — поиск в «сжатом» виде (без пробелов, для защиты
от разрядки). Там границ слов нет вообще, поэтому включать его нужно
**только** когда текст похож на попытку обхода: есть невидимые символы,
латиница вперемешку с кириллицей, разрядка или цифры внутри слов.
Иначе он даёт те же ложные срабатывания.

## 15. Обычная ссылка — слабый признак

**Симптом:** «Купил дрель за 12000, вот ссылка на магазин» удалено.

**Причина:** защита от ложных срабатываний обычно устроена так: если
не сработал ни один «контекстный» признак, оценка ограничивается низким
значением. Если засчитать **любую** ссылку как контекстный признак,
ограничитель снимается ссылкой на магазин или статью.

**Решение:** разделяй. Ссылка на Telegram-аккаунт или канал (`t.me/`,
`@username`) — признак объявления. Обычная ссылка — почти ничего не значит
и контекстным признаком не считается.

## 16. Антиспам самого Telegram работает параллельно

В группах от 200 участников админ может включить «Активный антиспам-фильтр».
Он удаляет часть спама **сам**, до вашего бота, и это меняет две вещи.

**Первое: удаление может не пройти — и это не ошибка.** Если Telegram снял
сообщение на долю секунды раньше, `delete_message()` вернёт «message to delete
not found». Не пиши владельцу «удаление не удалось» — проверь текст ошибки:

```python
except TelegramAPIError as e:
    if "not found" in str(e).lower():
        deleted = True          # уже снято антиспамом Telegram
    else:
        errors.append(f"удаление не удалось: {e}")
```

**Второе: он только удаляет, но не банит.** Спамер остаётся в чате и пишет
снова. Бан и чистку прошлых сообщений делает только твой бот, поэтому
одно другого не заменяет.

Проверить настройку можно из бота: `(await bot.get_chat(chat_id))
.has_aggressive_anti_spam_enabled`. Покажи её в состоянии — если админ
случайно выключит фильтр, владелец увидит.

## 17. `revoke_messages` не удаляет сообщения для остальных

**Симптом:** забанил спамера с `revoke_messages=True`, а его сообщения
остались висеть в чате.

**Причина:** параметр скрывает историю **от самого забаненного**, а не
удаляет сообщения для других участников. На это есть открытые баг-репорты.

**Решение:** запоминай номера сообщений каждого участника (только номера,
без текста — из них ничего не восстановить) и удаляй их явно:

```python
def remember_message(self, chat_id, user_id, message_id): ...   # при каждом сообщении
ids = self.store.user_message_ids(chat_id, user_id)
await bot.delete_messages(chat_id, ids[:100])   # не больше ста за раз
```

Это важно ещё и потому, что фильтр мог пропустить первые сообщения
спамера: когда он наконец попался, удалить нужно всё, что он успел написать.
Дольше 48 часов хранить номера бессмысленно — Telegram всё равно не даст
удалить.

## 18. Сумма с периодом оплаты — уже объявление

**Симптом:** «Помощник кладовщика. 4300 ₽ за день. Есть обучение.»
проходит фильтр, потому что ни одного слова из словаря в нём нет.

**Причина:** защита от ложных срабатываний требует «контекстного» признака,
а словарь не покрывает все профессии и формулировки.

**Решение:** считай сочетание «сумма + за день / за смену / на руки»
самостоятельным признаком объявления. Обычная фраза с суммой, но без
периода («заплатил за ремонт 45000»), под это не попадает.

Там же отдельный приём вербовки: **«Пиши "СКЛАД"», «Напиши "+"»** — просят
прислать кодовое слово. Регистр здесь важен, искать надо в исходном тексте:
«пишите в личку» строчными — обычная просьба, а не вербовка.

## Проверка перед сдачей

Диагностика едет на сервер вместе со всем проектом (она импортирует его
модули, отдельным файлом не работает). Запусти на сервере:

```bash
/opt/moderator/.venv/bin/python -m deploy.diagnose
```

Он проверяет всё перечисленное разом: токен, права в чате, режим приватности,
доступность лички владельца, список команд, работу фильтра, базу и возможность
сохранять настройки. Токен не печатает.

Не говори владельцу «всё работает», пока эта проверка не прошла целиком.
